# Module's gas yield can never be claimed and

## Description

Module's gas yield can never be claimed
The protocol is meant to be deployed on blast, meaning that the gas and ether balance accrue yield.
By default these yield settings for both ETH and GAS yields are set to VOID as default, meaning that unless we configure the yield mode to claimable, we will be unable to recieve the yield. The protocol never sets gas to claimable for the modules, and the governor of the contract is the auction house, the auction house also does not implement any function to set the modules gas yield to claimable.
```solidity
constructor(address auctionHouse_) LinearVesting(auctionHouse_) BlastGas(auctionHouse_) {}
```
The constructor of both BlastLinearVesting and BlastEMPAM set the auction house here BlastGas(auctionHouse_) if we look at this contract we can observe the above.
BlastGas.sol
```solidity
constructor(address parent_) {
    // Configure governor to claim gas fees
    IBlast(0x4300000000000000000000000000000000000002).configureGovernor(parent_);
}
```
As we can see above, the governor is set in constructor, but we never set gas to claimable. Gas yield mode will be in its default mode which is VOID, the modules will not accue gas yields. Since these modules never set gas yield mode to claimable, the auction house cannot claim any gas yield for either of the contracts.
Additionally the auction house includes no function to configure yield mode, the auction house contract only has a function to claim the gas yield but this will revert since the yield mode for these module contracts will be VOID.
Gas yields will never acrue and the yield will forever be lost

## Proof of Concept

no poc

## Recommendation

change the following in BlastGas contract, this will set the gas yield of the modules to claimable in the constructor and allowing the auction house to claim gas yield.
```solidity
interface IBlast {
    function configureGovernor(address governor_) external;
    function configureClaimableGas() external;
}

abstract contract BlastGas {
    // ========== CONSTRUCTOR ========== //
    constructor(address parent_) {
        // Configure governor to claim gas fees
        IBlast(0x4300000000000000000000000000000000000002).configureClaimableGas();
        IBlast(0x4300000000000000000000000000000000000002).configureGovernor(parent_);
    }
}
```

The vulnerability is a misconfiguration of the gas‑yield mechanism in the modules that are intended to run on the Blast network. By default the Blast protocol defines a yield mode called 'VOID', which disables the accumulation and claiming of gas and ether rewards. The constructor of the modules only calls IBlast.configureGovernor to set the auction house as the governor, but it never invokes IBlast.configureClaimableGas to switch the yield mode from 'VOID' to 'CLAIMABLE'. Because the auction‑house contract does not expose any function to change the yield mode, the modules remain in the 'VOID' state for the lifetime of the deployment. Consequently, any gas that would have been generated by the Blast network is never recorded, and the claimGasYield function in the auction house always reverts. The issue manifests when a user or protocol operator attempts to claim gas yield and receives no funds, often seeing a zero balance or an empty transaction log, which can be mistaken for a normal state rather than a loss. The root cause is the omission of a required initialization step and the absence of an administrative interface to modify the yield mode after deployment. This bug is hard to notice because the contract does not throw an error; it simply never accrues yield, so standard testing that only checks for successful transactions may miss the problem. The impact is economic: the protocol forfeits the expected gas revenue, reducing overall profitability and potentially breaking business logic that assumes periodic yield collection. The affected parties include the protocol developers, the auction‑house governor, and any token holders who expect the protocol to generate additional ether from gas yields. The flaw was discovered during a manual audit of the constructor code and the BlastGas abstract contract, where the missing configureClaimableGas call was identified. To remediate, the constructor should invoke configureClaimableGas before setting the governor, or a separate governance function should be added to allow the auction house to enable claimable yield after deployment. This change ensures that the modules transition to the 'CLAIMABLE' mode, allowing the auction house to successfully claim and distribute gas yields as intended.
